# 阅读指南

概论从业务承诺、身份与历史的角度串联全书。前两部分沿购买链路逐步建立协议，第三部分研究历史发生变化之后的保证，第四部分从完整架构讲解实际系统。全书结语回到这些机制之间的共同关系。

| 章 | 标题 |
| --- | --- |
| 1 | 先实现一个正常工作的下单服务 |
| 2 | 一次超时，为什么变成了两次扣款 |
| 3 | 系统怎样认出同一次购买 |
| 4 | 两个请求同时到达，第一版防重失效了 |
| 5 | 扣款已经成功，怎样把结果找回来 |
| 6 | 在每一步杀死服务，检验第一版协议 |
| 7 | 接入支付平台，本地事务的保证到哪里结束 |
| 8 | 支付一直停在处理中，谁来接着做 |
| 9 | 支付成功以后，可靠地通知下游 |
| 10 | 消费者处理完消息，却没来得及确认 |
| 11 | 切换到另一个副本，系统还记得做过什么吗 |
| 12 | 去重记录越来越多，能不能删掉 |
| 13 | 换一种业务表达，能少记住一些历史吗 |
| 14 | 恢复旧备份，再把流量切到另一个地域 |
| 15 | 给最终系统写下它能兑现的保证 |
| 16 | 总体架构、服务协作与业务链路 |
| 17 | 分区数据、复制与协调控制面 |
| 18 | Redis 节点、缓存与集群设计 |
| 19 | 分布式存储与跨分区事务 |
| 20 | 批处理、任务、Actor 与函数执行 |
| 21 | 多地域部署、容量运维与前沿架构 |

初次阅读可按章节顺序推进。已有事务基础的读者可结合第 15 章完整协议回看前文，再进入第四部分的系统架构。实验入口见 [examples](../examples/README.md)。
